Next.js on Workers (vinext)

FactStateSource
vinext is Cloudflare's recommended way to run Next.js on Workers. It is a Vite plugin that reimplements the Next.js API surface.✅ confirmedsource ↗
vinext is beta. Run npx vinext check before adopting it.✅ confirmedsource ↗
Supported: App Router, route handlers, RSC, Server Actions, SSR streaming, middleware. Bindings via import { env } from "cloudflare:workers".✅ confirmedsource ↗
npx vinext init adds dev:vinext/build:vinext scripts and vite.config.ts. By default it generates a typed cloudflare.config.ts; --legacy-wrangler-cloudflare-init keeps wrangler.✅ confirmedsource ↗
A custom worker entry can wrap vinext/server/fetch-handler. Exporting a DO class from the same entry is not documented.🟡 inferredsource ↗
Known gaps: "use cache"/PPR incomplete, build-time font/image optimisation missing.✅ confirmedsource ↗

Agents SDK

FactStateSource
The Agent class is a Durable Object with this.sql (tagged-template SQLite), this.state, setState() broadcast, schedule().✅ confirmedsource ↗
Clients connect with useAgent({ agent, name, onStateUpdate }). Endpoints follow /agents/:agent/:instance, routed by routeAgentRequest().✅ confirmedsource ↗
@callable() needs TC39 decorators. Under Vite 8, add the agents() plugin from agents/vite.✅ confirmedsource ↗
Wrangler needs: nodejs_compat; a DO binding; new_sqlite_classes migration.✅ confirmedsource ↗
Built-in tracing: observability.traces.enabled gives invoke_agent > chat / execute_tool spans with token usage in the dashboard Agents tab. 7-day retention, payloads may be truncated.✅ confirmedsource ↗
Custom spans: import { tracing } from "cloudflare:workers" then startSpan/enterSpan.✅ confirmedsource ↗
Agent state cap: 1 GB per instance.✅ confirmedsource ↗

Workers AI and Llama 3.3

FactStateSource

Response: { response, usage: { prompt_tokens, completion_tokens, total_tokens }, tool_calls: [{ name, arguments }] }.✅ confirmedsource ↗
max_tokens defaults to 256. Raise it explicitly.✅ confirmedsource ↗

Text-generation rate limit: 300 requests per minute.✅ confirmedsource ↗
Free: 10,000 Neurons per day, resets 00:00 UTC; calls fail with an error beyond it. Paid: $0.011 per 1,000 Neurons.✅ confirmedsource ↗
Llama 3.3 70B: 26,668 Neurons per M input tokens, 204,805 per M output tokens. Llama 3.1 8B fp8-fast: 4,119 / 34,868.✅ confirmedsource ↗
Workers AI has no local simulation. wrangler dev calls the real service, uses real Neurons, and needs login.✅ confirmedsource ↗

Free plan limits

FactStateSource
Workers Free: 100,000 requests/day; 10 ms CPU per invocation; 128 MB memory; 50 external subrequests.✅ confirmedsource ↗
Worker size: the limits page now states 64 MiB uncompressed on both plans. Older pages state 3 MB Free.🟡 conflicting docssource ↗
Durable Objects Free: SQLite backend only; 100,000 requests/day; 13,000 GB-s/day; 5M rows read and 100k rows written per day.✅ confirmedsource ↗
Workflows Free: 3,000 steps/day; 10 ms CPU per step.✅ confirmedsource ↗
Workers Logs Free: 200k events/day, 3-day retention.✅ confirmedsource ↗
CPU time excludes time spent waiting on I/O (LLM calls), so a long agent run is not CPU-bound.✅ confirmedsource ↗
⚠️
Limits that can bite

10 ms of CPU per request on Free is the main risk for Next.js server rendering (the Workers limits page says SSR typically uses 10–20 ms). It also matters for JSON-heavy route handlers. Keep pages client-rendered and payloads small. See risks.
