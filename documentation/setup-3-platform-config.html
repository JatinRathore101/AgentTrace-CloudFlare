vite.config.ts

// vite.config.ts — as generated by vinext init (repo root)
import { defineConfig } from "vite";
import vinext from "vinext";
import { cloudflare } from "@cloudflare/vite-plugin";

export default defineConfig({
  plugins: [
    vinext(),
    cloudflare({ viteEnvironment: { name: "rsc", childEnvironments: ["ssr"] } }),
  ],
});
// No agents() plugin: TraceAgent uses plain RPC methods, no @callable decorators (D22).

Worker entry

// worker/index.ts — single Worker: agent routes first, then the Next.js app
import handler from "vinext/server/fetch-handler";
import { routeAgentRequest } from "agents";
export { TraceAgent } from "../src/agent/trace-agent";

export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    return (await routeAgentRequest(request, env)) ?? handler.fetch(request, env, ctx);
  },
} satisfies ExportedHandler<Env>;
✅
Verified in the 2.1 spike (26 Oct 2026)

The custom entry exporting TraceAgent next to the vinext handler works in vite dev and in wrangler deploy --dry-run (bundle 2.34 MB, 657 KB gzip). getAgentByName(env.TraceAgent, "default") from agents 0.30.1 returns a typed RPC stub.

DO stub helper

// src/lib/agent-client.ts — used by every route handler
import { env } from "cloudflare:workers";
import { getAgentByName } from "agents";
import type { TraceAgent } from "@/agent/trace-agent";

export const getTraceAgent = () => getAgentByName<Env, TraceAgent>(env.TraceAgent, "default");

AI Gateway

  • No dashboard step. Only a gateway named default is auto-created by the first authenticated env.AI.run(..., { gateway: { id: "default" } }). A custom id such as agenttrace fails with AiGatewayError 2001 until it is created in the dashboard (found in the 2.1 spike, D20). ✅ confirmed
  • Optional: Dashboard → AI → AI Gateway → default → enable caching (off by default) and view logs, which are linked from spans via gateway_log_id.

Types

npx wrangler types   # generates worker-configuration.d.ts with Env { AI, TraceAgent, MODEL_DEFAULT, ... }

.dev.vars

Create an empty .dev.vars (git-ignored). If it is missing, Wrangler loads .env into the local Worker's env, which would expose the account ID and OAuth tokens to Worker code (D21). ✅ confirmed

Secrets

None needed. Workers AI uses the binding, so there is no API key. ✅ confirmed
