Order

  1. Preflight: npx wrangler whoami, npm run lint, npx vitest run, all green.
  2. Set the demo model: MODEL_DEFAULT = "@cf/meta/llama-3.3-70b-instruct-fp8-fast" in wrangler.jsonc.
  3. Build and dry-run: npm run build:vinext, then npx wrangler deploy --dry-run --config dist/server/wrangler.json. Check the bundle size in the output.
  4. Deploy: npm run deploy:vinext. On the first deploy, Wrangler applies migration v1 (creates the SQLite DO class) and may ask for the workers.dev subdomain.
  5. Note the printed URL https://agenttrace.<subdomain>.workers.dev and put it in the README.
  6. Run the verification below.

Verification

BASE=https://agenttrace.<subdomain>.workers.dev
curl -s $BASE/api/scenarios | jq '.scenarios | length'          # 3
RUN=$(curl -s -X POST $BASE/api/runs -H 'content-type: application/json' \
  -d '{"scenarioId":"tokyo-weather"}' | jq -r .runId)
sleep 20; curl -s $BASE/api/runs/$RUN | jq '{status: .run.status, spans: (.spans|length)}'
npx wrangler tail agenttrace --format pretty                    # live logs while clicking through the UI
  • Dashboard → Workers & Pages → agenttrace → Observability shows traces. The Agents tab shows invoke_agent spans.
  • Dashboard → AI → AI Gateway → default shows the model calls.
  • Runs list on the live URL shows the 5 seeded demo runs before any new run is started (TC25).

Rollback

npx wrangler deployments list
npx wrangler rollback            # previous version; DO storage is kept
⚠️
Migrations are forward-only

Rollback does not undo the v1 DO migration. Code-only rollbacks are safe because the schema is created with IF NOT EXISTS.
